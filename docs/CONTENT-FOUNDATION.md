Unity CreateScene/MoveGameObjectToScene creates and owns the canvas; its default physics scene uses the native Physics2D simulation. A separate physics world would require changing native global queries, so it is not introduced. The native GameCore registration remains unchanged in the proof. Scene ownership is therefore independent from the engine's registered service level; this is deliberate, not a claim that all bootstrap dependencies have been removed.

1. Identify the actual native asset/emitter and its source scene in the installed build. Add the source to the reviewed scene/type manifest before permitting its load; re-pin relevant build evidence. Never enable its original gameplay to acquire it.
2. Add a NativeContentKind and NativeContentDefinition with exact extraction and native inactive preparation. Initialize native dependency caches/pool interfaces, admit only owned nested graphs and identify any native services it requires.
3. Request it asynchronously through the repository; gate the consuming feature on Ready. Live encounter geometry changes need the same readiness gate as initial preparation. Loading an object is not readiness to take damage.
